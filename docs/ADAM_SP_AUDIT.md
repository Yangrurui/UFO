# G1 / Adam SP 适配与数据质量复查

> Historical audit of the earlier Adam retargets and screened split. The current full-data adaptation is documented in [ADAM_SP.md](ADAM_SP.md), with the updated [862-clip review](../../adam_sp/comparison_full/review.html).

本次结论：Adam 的仿真、训练和导出接口已接通，但当前数据还不能视为完整的 G1 等价数据集。主要缺口是动作覆盖、根节点时序平滑、接触脚高度，以及跌倒起身的多点支撑。此前约 3 mm 的脚部 IK 误差是相对 Adam 自己构造的目标，不能用于证明优于 G1，也不能证明动态可跟踪。

本次只新增审计脚本、统计、图表和同帧回放，没有修改机器人参数、已筛选训练数据或正在运行的 G1 任务，没有启动 Adam 正式训练。

## 比较口径

- 从正在运行的 G1 保存配置追溯到实际使用的 `lafan_29dof_10s-clipped.pkl`，并非使用下载的全部 77 个 BVH。
- G1 使用 40 个源动作、862 个 300 帧片段，30 Hz，共 258,600 帧、143.67 分钟。
- Adam 候选集采用同样的 40 个动作及 862 个区间，无开头裁剪、无时间缩放。
- 40 个 G1 完整动作的帧数均等于原 BVH；原始人体与 G1 根部水平速度相关系数为 0.924–0.999，在 ±90 帧范围内的最佳对齐均为 0 帧。
- 分别重放两个机器人的全部帧：总计 517,200 个姿态。用当前训练 MJCF 的碰撞体、排除规则和关节限位，加 z=0 地面，执行 CPU MuJoCo `mj_forward`。
- 所有导数在每个 10 秒片段内部计算，不跨片段边界。支撑标签由原始 BVH 脚趾高度和速度推断，两边共用同一标签；脚滑指标是支撑期踝节点 XY 速度，包含脚掌滚动影响，不是力传感器测量。
- 实际 MotionLib 两边均默认 `no_fix`，不会自动修复这些地面问题。G1 的 `pose_aa` 与存储 `dof` 一致；Adam 的 `dof_pos` 保留了倾斜关节轴下正确的标量关节角。
- G1 与 GMR 数据整体世界朝向约差 90°。回放中仅对 Adam 施加固定 +90° 全局旋转，以便观看；训练文件、关节角和时间均未改变。下述 XY 速度、加速度范数与碰撞统计不受此旋转影响。

这些碰撞结果描述“该参考动作在当前机器人的原生碰撞体下是否可行”。G1 有 33 个有效碰撞体、4 对显式身体排除；Adam 有 37 个、2 对。两套几何不同，不能把碰撞比例直接解释成 retarget 算法排名。G1 官方数据也不是严格的无碰撞、无穿地真值。

使用共同的运动学门槛（越界、超速、自碰撞、穿地、支撑期脚速），G1 通过 2/862，Adam 通过 191/862。这个门槛非常严格：单帧超过阈值即可淘汰整个片段，它不是 UFO 官方的 G1 数据筛选标准，更不是策略训练成功率。Adam 另外还检查 IK 目标误差、根部投影及根速度，最终保留 181/862。

Adam 的 630 个片段因超过 10 mm 自碰撞被拒收，但对应违规帧只占 3.87%。这说明后续应优先修复局部困难区间，而非直接降低门槛或一直扩大整段丢弃范围。主要碰撞是手腕与同侧髋、前臂与髋、手腕与躯干。

| 最大自碰撞穿透 | 90.67 mm | 9.97 mm |
| 最大穿地 | 25.57 mm | 0 mm |

腿长定义为零位下髋 yaw 到膝、膝到踝 roll 两段距离之和：G1 0.5114 m，Adam 0.7407 m。两者相差 1.448 倍，因此不能只凭未经归一化的脚速判断 Adam 更差；归一化后两者脚速 P95 基本相同。

根节点加速度归一化后 Adam 仍为 G1 的约 **2.48 倍**，接触脚高度约 **1.94 倍**。这两个差异不能仅用体型解释，是本轮最重要的数据问题。当前质量门槛未覆盖根加速度和接触脚悬空，原来的“181 段通过”并不等价于完整质量达标。

Adam 被动关节限速已有效，但在保留片段中仍有 5.69% 的相邻帧达到接近限速状态；这可能迫使姿态追踪让步，应结合时序优化处理，而不是单纯继续压低 IK 位置误差。

## 哪些必须单独为 Adam 适配

已经正确区分：29 个控制关节的真实顺序、倾斜关节轴、腰 roll/pitch/yaw 顺序、wrist-yaw/pitch/roll 链、wrist-roll 手端、前臂坐标系旋转、默认关节角、脚底碰撞几何、质量惯量、PD、力矩/速度上限、armature、摩擦与被动阻尼。Adam 模型质量约 62.10 kg，G1 约 33.74 kg，不能把 G1 的绝对电机参数照搬过来。

Adam MJCF 的被动阻尼由运行时保留，PD 的 kd 作为主动控制另行使用；armature 和摩擦按配置覆盖，并非重复相加。配置来源是本地 XLab 的基础 29-DoF profile，不等于已经使用该项目另一套实测扭矩-转速包络或带延迟 profile。

仍需处理，按优先级排序：

1. **根部时序与接触相位**：在连续窗口内联合优化根位姿、关节和平滑项，同时施加支撑期脚底高度和速度约束。避免只对输出做低通滤波，造成新的穿地或接触错位。补充根加速度、接触脚高度、限速占比的审查；不能将现有 181 段全部视为最终训练集。
2. **跌倒起身和残余碰撞**：全部 90 个跌倒起身片段未进入 Adam 数据。现有 IK 只约束机器人自身碰撞，地面修正主要围绕脚底；需要手、膝、髋、躯干参与的地面约束和多点支撑阶段。当前被拒收片段最大穿地约 0.50 m，不能进入训练。
3. **奖励的物理尺度**：为可复现基线先保留相同形式与系数。Adam 更重、力矩更大，绝对扭矩平方惩罚、速度惩罚和脚部姿态惩罚的实际强度可能不同；需要根据动态 rollout 的分项统计决定是否归一化，当前运动学报告不能替代这一步。
4. **动态可行性**：无越界、无超速、低 IK 误差仍不证明所需力矩、接触力、平衡可行。现有 4096 步 / 60 次更新是接口 smoke，应另行验证固定参考跟踪或逆动力学可行性，再扩大正式训练。
5. **硬件与部署**：Adam 的通信协议、关节映射、IMU/坐标约定、实际命令延迟、电机包络需要专用部署配置。当前仓库文档明确 deploy 分支面向 G1；ONNX 结构检查通过不代表可以直接上 Adam 实机。

G1 YAML 中若干遗留 retarget/对称字段并不被当前 FB MJLab 训练和推理消费，不能仅为了字段数量一致给 Adam 填入未经验证的值。
